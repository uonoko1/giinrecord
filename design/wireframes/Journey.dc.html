ユーザーの動線（選挙の2週間前〜投票日）
「候補者が言っていること」ではなく「やってきたこと」を、投票所に行く前の数分で確かめたい人。
きっかけ
選挙公報・ポスター・SNSで候補者名を知る
現職なら国会での記録がある。新人は記録なし＝「記録がない」と正直に出す
→
入口①
名前で検索
Google検索 → 議員ページに直接着地が最多。サイトのトップを経由しない前提で設計する
→
中核画面（S1）
議員ページ：事実の時系列
採決での賛否 / 提出・賛同した法案 / 本会議での発言。すべて一次資料リンク付き。評価はしない
→
次の行動（S2〜S3）
法案を深掘り / 他候補と比較
「この法案、他の人はどうだった？」→ 採決ページ。「同じ選挙区の別候補は？」→ 比較
入口②
争点法案から逆引き
SNSで「○○法案の賛否一覧」が共有される → 採決ページ → 気になる議員へ
入口③（S3）
自分の選挙区から
郵便番号 → 選挙区の現職・元職 → 比較ページ
設計上の約束（全画面共通）
・1行の事実ごとに原典（参院投票結果／衆院経過／会議録）へのリンク
・「事実」と「推定（会派ベース）」を視覚的に区別
・スコア、ランク、色による善悪表現を使わない
・データの取得日時を常に表示
