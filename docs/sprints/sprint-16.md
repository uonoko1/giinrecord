Sprint 15 で作り直しが完走し、委員会の発言（#242）と役職（#244）が本番に届いた。
それでも**個人の記録がゼロの議員が 49 名いる**。

```
（main の data/members/*.json の timeline を走査。2026-08-30）
衆院: 465 名中 42 名
参院: 307 名中  7 名
```

利用者から見れば**何も分からないページ**が 49 ページある。そして今は、それが
「本当に活動がない」のか「取得しているが紐づいていない」のかを**区別できていない**。

**発言は取得できたのに紐づかなかったものが 692 件ある**（`data/unmatched.json`）。
ここに 49 名ぶんが含まれていれば、**直せば記録が増える**。含まれていなければ
「一次資料に無い」という別の結論になる。**どちらであってもそれが答え**で、
いま欠けているのは「どちらか分かっていない」ことそのものである。

## 着手順

## #308 の進め方（原因を特定してから直す）

Sprint 15 で調べた範囲では原因が分からなかった。**fail2ban も OOM の記録も無く、
ディスクも 32% で余裕がある**（メモリは 1.9GB と小さい）。

- **リトライで隠さない。** 原因が分からないまま `retry` を足すと失敗が見えなくなるだけ
- **再現時にサーバ側が何を返して切っているか**を採る（`rsync -vv`、`sshd` の `LogLevel VERBOSE`）
- **対策後は連続成功を実測で示す。** 1 回の成功は根拠にならない

## 測ってから決める（前スプリントの成果）

**#275 は実測で「対応不要」になった。** 起票時は「必ず当たる」としていたが、
本番の実サイズは 25.6MB（上限 50MB の 51%）だった。

同じ理由で、**今スプリントでは「発言タブが重い」を起票していない**。測ったところ：

```
speeches.json: 696 件 / 最大 0.87MB / 中央値 50KB / 1MB超 0 件
本番（最大の議員 m_010045）: gzip 転送量 239,701 bytes、所要 0.187 秒
```

**問題が無いので起票しない。** 起票してから「対応不要」と閉じるのではなく、
**起票する前に測る**。
