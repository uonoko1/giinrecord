### #308 は原因を特定した（`rrsync` の排他ロック）

**失敗ログのエラーの直前の行に、そのまま出ていた。**

```
/usr/bin/rrsync error: Another instance of rrsync is already accessing this directory.
rsync: connection unexpectedly closed (0 bytes received so far) [sender]
```

deploy 鍵は `authorized_keys` の `command=` で `rrsync /var/www/giinrecord` に固定されており、
**rrsync は制限ルート全体に `flock(LOCK_EX|LOCK_NB)` を掛ける**。`site/` と `staging/` は同じロックを
奪い合うが、`concurrency` group が `deploy-<target_dir>` と dir ごとに分かれていたのですり抜けていた。

`group: deploy-vps`（ロックの単位）に変更。`deploy-site.yml` の呼び出し元3つが**これ1つで直列化される**。

マージ直後に新旧が同時に走り、**旧 group のほうだけが落ちた**ことで診断が裏付けられた:

```
run=33310255666 sha=0913dfbb 11:58:34→11:59:22 failure  [group: deploy-${{ inputs.target_dir }}]
run=33310258033 sha=79cd3a9c 11:58:39→11:59:28 success  [group: deploy-vps]
```

**#308 は開けたままにしている。** 受け入れ条件の「対策後、連続して成功することを実測で示す」が
まだ満たせていないため（成功は再実行1回ぶんで、根拠として弱い）。

## レトロスペクティブ（検査と適応）

### 1. 「取れない」を2回、正当な結論として出せた

**#309**（記録ゼロの49名）と **#316**（衆院の過去回次）は、どちらも**「直せない」で終わった**。
そしてそれは失敗ではない。

- #309: 衆院42名を**1名ずつ会議録 API に問い合わせ**、全員 `numberOfRecords=0` を実測
- #316: 官報・総選挙の結果・会議録 API を**実際に取得して**確かめた。総選挙の結果は
  氏名が投票用紙の通称で、**同じ総選挙の当選者で照合して 289 人中 80 人しか一致しない**

**両方とも `/coverage/` に「調べたうえで無い」と書いた。** #274 が参院について
「参議院のサイト以外の一次資料は調べていません」と**主張の範囲を限定した**のと対になる。
今回は範囲を広げて調べたので、そう書ける。

### 2. 起票する前に測った

「発言が 85,068 件に増えたので発言タブが重いのでは」を検討したが、**測ったら問題が無かったので起票しなかった**。

```
speeches.json: 696 件 / 最大 0.87MB / 中央値 50KB / 1MB超 0 件
本番（最大の議員）: gzip 転送量 239,701 bytes、所要 0.187 秒
```

Sprint 15 の #275 は「必ず当たる」と起票してから実測で「対応不要」と閉じた。
**起票してから測るのではなく、起票する前に測る**に変えられた。

### 3. 同じ失敗を4回繰り返した（テストが何も守っていない）

**#244 → #308 → #313 → #320。** いずれも「テストを書いた。緑になった」で止めた。

- **#308**: 行末コメントを含む生文字列に正規表現を当て、
  `group: deploy-${{ inputs.target_dir }}  # deploy-vps` を素通しした
- **#320**: 「変更を**丸ごと削除**する」戻し方では落ちたが、
  **設計の要点だけを無効化する**変異（`byGroup` → `candidates`）では通った

**1通りの戻し方では足りない。** 作業合意（#322）に3通りの壊し方を明記した。
落ちない変異が**等価変異**ならそう書いて残す（#320 の `<2` → `<0`）。

### 4. 「緩めていない」と書きながら2回緩めていた

#320 で「在職確認は緩めていない」と書いたが、**2箇所で実際に緩んでいた**。

```
（自己レビュー）main: X党で照会 → m_A       初版: → h_B（Y党の別人）
（レビュー指摘）main: group=undefined → undefined   前版: → h_B（別人に確信を持って紐づく）
```

どちらも **`origin/main` の worktree を作って同じ関数を同じ入力で叩いて**初めて分かった。

**設計上の学び**: 絞り込みの手がかりには**強さの順序がある**。名簿に書いてある事実（会派）は、
記載からの推論（(a)/(b) の別）より強い。**弱い手がかりを先に効かせると、強い手がかりで直せなくなる。**

### 5. 症状で grep して、答えを読み落とした（#308）

`connection unexpectedly closed` で grep し、**その1行上を読まなかった**。

```
/usr/bin/rrsync error: Another instance of rrsync is already accessing this directory.
rsync: connection unexpectedly closed (0 bytes received so far) [sender]
```

**取得済みのログの中に答えがあった。** さらに「再現できなかった」根拠にした実験は
`rrsync` を経由しておらず（`-n` で `/tmp` 宛て）、反証になっていなかった。
