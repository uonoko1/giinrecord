## データサイズの前提（#263 で**実測に置き換え済み**）

PO が事前に出していた推定は、**#263 の実測で3点が覆った**。推定のまま設計しなくて正解だった。

| | PO の推定 | **#263 の実測** | ずれ |
|---|---|---|---|
| 発言1件のバイト数 | 534B（本会議からの回帰） | **768.5B** | 1.44倍。会議名が長い・`position` が41%に付くため |
| 22回次の件数 | 1,551,968件（×22 の外挿） | **797,651件** | 外挿が**1.95倍の過大** |
| `data/members/` の増加 | 約0.71GB | **約455MB**（90MB→6.1倍） | — |
| 議員に紐づく割合 | 84%（298件サンプル） | **77.87%**（全量） | サンプルが予算委員会に偏っていた |

その他の実測（`docs/research/committee-speeches.md`）:

- 第221回を**全量取得できた**（衆33,380／参37,164＝70,544件。`numberOfRecords` と完全一致）
- **レコードの形は1種類だけ**（21キー固定）。連合審査会・公聴会・調査会も同一構造で、
  **既存パーサは無改造で通る**。島根型の失敗リスクはこの API では低い
  （ただし第221回は特別会で**分科会・両院協議会が存在せず、そこは未確認**）
- 通常国会6回次（201・204・208・211・213・217）だけで**全体の71.5%**。
  **「どこまで遡るか」がサイズを決める最大の変数**

### #242 で併せて決めること（#263 の結論）

1. **収録範囲**: 22回次（455MB / 8,000ページ / 2.2時間）か、直近数回次か。第221回だけなら 40MB / 12分
2. **発言を全件プリレンダーするのをやめるか**。**これが効き所**。
   `ssr: false` のプリレンダーは**折りたたんだ回次も含めて HTML に全件焼き込む**ため、
   ファイルを `members/{id}/speeches.json` に分けても**それだけではモバイルは1バイトも軽くならない**
   （実測: HTML は元 JSON の2.15倍）。「発言タブだけ実行時 fetch」など**描画側の変更とセット**が要る
3. **本文（`excerpt`）は捨てない**。捨てれば gzip 1/12.7 まで落ちるが、
   `excerpt` は原文冒頭200字で**議員ページで実際に読ませている唯一の発言内容**。
   これを消すと「発言した」という事実だけが残り、**「何をしたか」を見せるという目的を損なう**
