# レトロスペクティブ

## 1. 「機能はあるが到達できない」は、テストでは見つからない

`ThemeToggle.test.tsx` は**通っていた**。コンポーネント単体としては正しく動くからである。
しかしそれを描画しているページが無いので、**ユーザーには存在しない機能**だった。

さらに `docs/ops/deploy.md` は CSP 障害の症状として「テーマ切替が動かない」を挙げており、
**動く前提で書かれていた**。ドキュメントと実装の食い違いが、誰にも気づかれずに残っていた。

**適応**: 「この機能はどのページから使えるか」を、実装ではなく**本番を触って**確かめる。
`grep -rn "<ComponentName"` で描画箇所を数えるのは1コマンドで済む。

## 2. 検査を足すときは「入れる前に落ちる」ことを実物で確かめる

`browser-check` にテーマの検査を足したとき、**#365 のリリース前に本番へ向けて走らせて落ちること**を
先に確認した:

```
（リリース前）browser-check: 1 failure(s) — waiting for locator(...input[value=dark])
（リリース後）browser-check: ok (10 pages)
```

これは「テストを書いて緑になった」より強い。**その検査が実際に何かを捕まえる**ことの証明になっている。

## 3. 自分で入れたテストの不安定さを、その場で直した

#361 / #363 で足した折りたたみのテストが、**フルスイートだと時々タイムアウト**していた
（単体では通る）。数百行を描画したうえで `userEvent.click` を使っていたためで、
`fireEvent.click` に変えた。3回連続で全件 pass を確認している。

**「単体では通る」で済ませない。** フルスイートで落ちるなら、それは落ちるテストである。
気づいたのは #365 の作業中に無関係な失敗が出たからで、**自分の変更のせいか調べる過程で分かった**。
`git stash` して同じ失敗が出ることを確認する手順が効いた。
