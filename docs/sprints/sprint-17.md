### #326 発言タブが折りたたまれていなかった

```
（本番の実ブラウザで確認。https://giinrecord.jp/members/m_003005/）
  描画された行数: 200
  ボタン: 「さらに表示（残り1,254件）」
  DOM ノード: 1,619        ← 修正前 10,664
```

**これは「測ったら本当に問題があった」例。**

```
発言タブ（1,454行）: 293 / 327 / 349 ms   ← 4x CPU throttle、幅390px
同ページ採決タブ（287行）: 43 / 71 / 82 ms
long task: 単一 319ms（TBT 269ms）
```

行数5倍で所要も4〜5倍。転送・parse は問題なし（502,994 bytes の JSON parse が 3〜6ms）で、
**描画側**だった。#275 と発言タブの転送量は測って「対応不要」で閉じたので、**測ってから決めるは
直さない理由にも直す理由にもなる**ことが両方そろった。

`STANCE_FOLD`(20) を流用せず **`SPEECH_FOLD`(200)** を分けた。発言は回次ごとの `details`（#103）に
入るので、20 で切ると**最新回次（第221回=379件）の頭だけ**を見せて残りを隠すため。
200件超は 697 名中 155 名（実測）。

## レトロスペクティブ（検査と適応）

### 1. `release.yml` も「本番に届いた」の証明にはならなかった

#325 の修正4点のうち、**3点は release で届き、1点（nginx の 404）だけ届かなかった**。

`release.yml` が rsync するのは**ビルド成果物だけ**で、`deploy/` は対象外である。
`deploy/nginx/site.conf` は VPS の `/opt/giinrecord`（root 所有の git チェックアウト）から
**bind mount** されており、`git pull` + `--force-recreate` が別途要る（`docs/ops/deploy.md:44` に既出）。

**手順は文書にあったのに、PO が「リリースした」で終わらせていた。** 本番を叩いて初めて気づいた。

**適応**（作業合意 #331 に追加済み）:
- **`deploy/` を触る PR には、VPS 側の反映手順を PR 本文に書く**
- **自動クローズされた issue が「完了」とは限らない。** #325 は PR のマージで閉じたが
  本番はまだ 200 だった。**本番で確かめるまでは開け直す**（実際に開け直した）

### 2. 実機で試すテストが、文字列検査より強かった

`deploy/test/nginx-404.test.sh` は**本物の nginx を起動**して実ステータスを見る。
PO が独立に走らせて 20/20 pass、さらに変異2種（`error_page 404 =200`／`location = /compare` の削除）で
**7件・2件が落ちる**ことを確認した。

**変異1（`=200`）は、設定ファイルの文字列を検査するテストなら素通りする形である。**
「設定が書かれているか」ではなく「**設定が効いているか**」を見ると、テストは格段に強くなる。

### 3. 担当が自分で「素通りするテスト」を見つけた

#325 の担当は、404 画面の `/coverage` 導線を `/about` に差し替える変異が**最初は通ってしまった**と
報告した。`screen.getAllByRole("link")` がページ全体を見ており、`SiteFooter` も `/coverage` を
貼っているため、**本体から導線を消してもフッターの分で緑になる**状態だった。`within(main)` に直している。

**#244 → #308 → #313 → #320 と同じ形**だが、今回は**担当が自分で見つけた**。
Sprint 16 で作業合意（#322）に「3通りの壊し方で確かめる」を入れた効果が出た最初の例。
