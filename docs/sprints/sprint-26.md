## この回でいちばん重い発見

**「無い」と書いてあることも、確かめないと信じられない。**

| | 前 | 後 | 何が起きていたか |
|---|---|---|---|
| **熊本** | 総数のみ | **公開** | 個人票が同じページの **PDF リンク 60 本以上のうちの 1 本**に埋もれていた |
| **山梨** | 不明 | **公開** | 2 階層下にあった |
| **滋賀** | 不明 | **公開** | `?KaigiID=` が要るだけだった |
| **佐賀** | 不明 | **公開** | 「議案件名一覧表」を 1 階層下りると個人別があった |

**「不明」も「総数のみ」も、「調べた上でそうだった」ではなく「そこまで到達できなかった」だった。**
**Sprint 25 で書いた「見つけたものをそのまま『直すべきもの』と読まない」の裏返しで、
「無い」と書いてあることも同じように疑う必要がある。**

**実装対象が 5 県 → 9 県に増えた**（#537 の判断の対象も 7 県 → 最大 16 県に）。

## 落としたもの

**ボードを一度も動かしていなかった。**

```
Issue 260 件のうち Project に載っていたのは 103 件（157 件が未登録）
非 Done の 15 件のうち 13 件は既に CLOSED のまま放置
ボードの最新は #260、Sprint 25 の作業（#632〜#668）は 1 件も載っていない
```

**`scripts/po/board-set.sh` は Sprint 4 から存在していた。使っていなかっただけ。**

**同じ形をもう 1 つ**——**`scripts/po/merge-when-green.sh` も使っていなかった。**
`gh pr merge` を直接叩き、待機ループを毎回自分で書いていた。
**このスクリプトは `BEHIND` なら `update-branch` まで自動でやる**ので、
担当者に rebase を頼む必要が無かった回が複数あった。

**教訓**: **道具があるのに使っていないことは、道具が無いことより気づきにくい。**
**`docs/ops/board.md` には両方とも書いてあった。**
