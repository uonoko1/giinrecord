### 3.2 突合方針の提案 — 推定しない

`match-votes.ts` の突合は「正規化氏名で候補を集め、複数なら会派で絞り、1人に絞れなければ `memberId` は空のまま `unmatched.json` に載せる」。名簿が無い回次では候補が 0 なので、**第142〜199回の票は全件 `unmatched` になる**。これは壊れではなく、`memberId` を推定で埋めないという既定の方針がそのまま働いた結果。

氏名だけで現職の `m_` に紐づけるのは危険で、やってはいけない:

- 第142回の `阿部　　正俊` と現職の同名者が同一人物である保証が無い。`memberId` は参院プロフィール ID の下 6 桁から作る永続 ID で、当時の議員にはプロフィールページ自体が無い
- 20 年以上の隔たりがあると同姓同名は現実に起こりうるし、`match-votes.ts` が同名分離に使う「会派で絞る」手が、比較対象の名簿が無いので効かない

代わりに取れる材料（いずれも**紐づけの根拠にはせず、記録として並べるだけ**）:

- **会議録 API の発言者情報**: `speaker`（氏名）に加えて `speakerYomi`・`speakerGroup`（会派）・`speakerPosition` が第142回でも入っている（下の 4 節に実応答）。会派名は投票結果ページの `caption.party` と同じ表記系（`民友連`）。ただしこれは**その日に発言した人**の情報で、在籍者名簿ではない。採決に参加した 215 人のうち発言するのは数人なので、名簿の代わりにはならない
- **議案の経過ページ・議案情報の氏名**: 発議者の筆頭者のみで、`docs/research/sangiin-cosponsors.md` の結論どおり全員は載らない

現実的な扱いとして提案するのは次のどれか:

1. **氏名表記のまま公開する**（推奨）。`RollCall.votes[].nameText` は既に原文を持っている。`memberId` が空の票を「誰の票か議員ページに紐づかない記録」として出し、`unmatched.json` に全件載せる。第142〜199回の採決そのもの（案件名・総数・会派別の賛否・個人の氏名と賛否）は一次資料どおり正確で、これだけでも価値がある
2. **回次別に会派＋氏名のスナップショットを投票結果ページ自身から作る**。個票の `caption.party` は会派名と人数（`自由民主党(119名)`）を持ち、その下に会派の全員（投票しなかった人も `投票なし` として）が並ぶ。つまり**採決日時点の会派別在籍者一覧が投票結果ページ自体に入っている**。これは名簿の代用になりうるが、あくまで「その採決ページに載っていた氏名と会派」であって参院公式の議員名簿ではないので、`Member` として公開するなら出所を別立てにし、`m_` 空間には入れないこと
3. 紐づけは将来 Issue に切り出し、この PBI では 1 だけをやる

`memberId` の推定は選択肢に入れない。

## 5. 実装 PBI（#219）のスコープ提案とリスク

### やること（提案）

1. **取得回次を第142〜199回に広げる**。`sessions.ts` の回次計画に手動実行の範囲として足すだけで、`sangiin-votes.ts` のパーサは**変更不要**（3 点のサンプルで旧レイアウト判定・会派ブロック・票セルがすべて一致）
2. 第142・145・150回の個票と第142・199回の一覧をフィクスチャに固定して、旧レイアウトのテストを 1998〜2000 年のページで通す
3. 名簿が無い回次の票は `memberId` 空・`unmatched.json` に全件、という現行の挙動をそのまま通す。`unmatched` が空でなければ非0終了する現行の cli の作り（`sessions.ts` の注記）に**引っかかるので、そこは分岐が要る**（下のリスク参照）
4. 衆院議案は第142回まで一覧が同構造で取れる。`規則の一覧`・`規程の一覧` の 2 種類への対応と、経過ページに会派態度が無い回次への対応（無い＝空。無いことを「全会派賛成」等に読み替えない）を足す
5. `/about` の「記録にないこと」に、第142〜199回は議員ページに紐づかない旨を書く

### リスク

| リスク | 中身 | 手当て |
|---|---|---|
| **`unmatched` の量** | 第142〜199回は全票が `memberId` 空。第142回だけで採決 177 件 × 200 人規模。cli は `unmatched` が空でなければ出力せず非0終了する作りなので、そのままでは ETL が通らない | 「名簿が無いと分かっている回次」を `unmatched` の異常判定から外す（回次で明示的に許可し、黙って通さない方針は保つ） |
| **全件の構造確認をしていない** | 実際に見たのは一覧 9 点・個票 3 点・衆院 3 点。第142〜199回は 58 回次あり、途中でレイアウトが切り替わる回次を見落としている可能性がある | パーサは既に「読めなければ `RollCallParseError` を投げる」作り。実装時は全回次を通しで走らせ、失敗した回次を潰す。推定で埋める分岐は足さない |
| **和暦だけの個票** | 見た 3 点はすべて `1998年 1月 14日` と西暦。`parseDate` は西暦しか読まない | 全回次実行で `日付が取得できません` が出た回次を個別に見る |
| **未知の会派** | 当時の会派（`民友連`・`新社会党・平和連合`・`参議院の会`・`二院クラブ・自由連合`・`自由民主党・保守党` 等）は `sangiin-groups.ts` に無い | `unmatched-groups.json` に出るので、実物を見て表に足す（推定で寄せない） |
| **衆院の未知の議案種別** | 第142回に `規則の一覧`・`規程の一覧` | `BillKind` に足すか、未知種別として素通しする |
| **衆院の会派態度が無い** | 第142回の経過ページ（`keika/5516.htm`）に `衆議院審議時会派態度`・`賛成会派`・`反対会派` が 1 件も無い。いつの回次から載るかは未確認 | 無いときは空にする。無いことを「全会派賛成」と読み替えない。回次を刻んで境界を確かめるのは実装時 |
| **取得量** | 第142〜199回で参院の個票が数千ページ規模（第142回 177・第145回 205・第180回 139…） | PoliteFetcher の ≥1s を守ると数時間かかる。日次 ETL には載せず、手動実行の一度きりの遡及として回す（第200〜216回を手で足したのと同じ運用） |
| **会議録 API の委員会側** | 参院本会議しか実応答を見ていない。`kokkai-attendance.ts` の出席者パースが 1998 年の委員会会議録でも効くかは未確認 | #219 のスコープからは外し、必要になったら別途調べる |

### スコープから外すことの提案

- **第142〜199回の票を現職の `memberId` に紐づけること**。名簿が無い以上、氏名一致は推定。やらない
- 衆院の会派態度から個人の賛否を作ること（現行方針どおり、期間に関係なくやらない）
- 会議録 API から在籍者名簿を組み立てること（発言者は在籍者の一部でしかない）
