## 結論（先に）

**確認できない。回次ごとの衆院議員の在職を、機械的に取得してよい一次資料から確定することはできない。**

#316 が挙げた 4 つの経路の結果:

1. **会議録 API に所属院・会派はある。しかし在職名簿にはならない**（発言者は在籍者の一部でしかなく、集合が閉じない）。実測で再確認した（3 節）
2. **衆院サイトに会期ごとの名簿は無い**（#245 の追認。回次を入れた URL は 400 を返す。2 節）
3. **官報は「取ってはいけない」。** robots.txt が本文の置き場（`/20…`・`/old/`）を Disallow しているだけでなく、**利用規約が散文で「検索ロボットやクローラによるデータ収集」を明示的に禁止**している。加えて**無料で読めるのは発行から 90 日だけ**で、過去回次はそもそも範囲外（4 節）
4. **選挙の期日（総選挙）からの期間としての確認は、総務省の資料では成立しない。** これが本調査でいちばん手数をかけた部分で、**「在るのに使えない」ことを実測で示した**（5 節）

**4 が本調査の新しい発見なので、要点を先に書く。** 総務省の「衆議院議員総選挙結果調」は第44〜51回（2005〜2026 年）が公開されており、**カバー範囲は申し分ない**（`data/` の第195〜221回は第48〜51回の 4 回の総選挙に収まる）。robots.txt も汎用 UA を妨げない。**それでも名簿にならない理由は 3 つある**:

- **PR（比例代表）の当選者を機械的に取り出せない。** 当選者名簿にあたる (11) の PDF は、**`当`/`落` の印が氏名とは別の段組に入っており、テキスト抽出では氏名と対応づかない**。実測: 氏名らしき行 600 行に対し、`当`/`落` が行頭に付いたものは **0 行**。176 の比例当選者を落選者から区別できない
- **氏名が名簿の氏名と一致しない。** 選挙資料の氏名は**通称（ボート上の表記）**で、名簿の氏名とは別物。**第51回（現在の名簿と同じ総選挙）の小選挙区当選者 289 人ですら、現在の名簿と一致するのは 80 人（27.7%）**
- **ふりがなが機械的に取り出せない。** `memberIdFromName(name, kana)` は氏名＋ふりがなのハッシュなので、**kana が作れなければ既存の ID 体系に載らない**

そして**仮に上の 3 つがすべて解けても、まだ足りない**。#316 が自分で疑っているとおり、**総選挙の当選者は「その総選挙で当選した 465 人」であって「第N回国会の在職者」ではない**。補選・辞職・死去・繰上補充が反映されない（6 節）。**総務省の資料には、任期中の異動を記録した資料が無い。**

**したがって #316 の受け入れ条件は「取れないなら `/coverage/` に書く」の枝に進む。** 文案は 7 節。

## 1. 何を「在職の確認」と呼んでいるか

`packages/etl/src/cli.ts:59` は `memberSession = Math.max(...plan.all)` として**最新回次の名簿だけ**を取り、`rosterCoveredSessions()` の外は紐づけない。必要なのは**「第N回国会の会期中に議員だったのは誰か」という閉じた集合**であって、次のどれでもない:

- 「第N回に発言した人」（在職の**十分**条件。発言しない議員が漏れる）
- 「第N回の議案に名前が載った人」（同上）
- 「総選挙で当選した 465 人」（会期の開始時点であって、**会期中の異動を含まない**）

この区別が本調査の全体を貫いている。**3 節・5 節で落ちるのは、いずれも「集合が閉じない」ためである。**

## 3. 会議録 API に所属院・会派の情報があるか → **ある。しかし名簿にならない**

`speechRecord` のキーは 20 個で、発言者に関するものは 4 つある（第220回衆議院、`numberOfRecords` 16、2026-08-30 取得、HTTP 200）:

```
speaker  speakerYomi  speakerGroup  speakerPosition  speakerRole
```

**氏名・ふりがな・会派が揃う。** #316 の「所属院・会派の情報が無いか」への答えは**「会派はある」**。ただし `nameOfHouse` は**会議の院**であって発言者の院ではない（#313 が同じ事実を扱っている）。

### 名簿にならないことの実測（本調査で測り直した）

第217回・衆議院（`numberOfRecords` **55,126**）から、`startRecord` を 1・3,000・9,000・15,000・21,000・27,000 の 6 か所に散らして各 100 件、計 **600 件**を取得した:

| 項目 | 値 |
|---|---|
| サンプルした発言レコード | **600** |
| `speakerGroup` あり（＝議員とみられる） | **495**（83%） |
| **異なり発言者（氏名＋ふりがな）** | **63 人** |

**600 レコードを 6 か所に散らして引いても、異なり発言者は 63 人**（定数 465 の 14%）。発言は委員長・大臣・質疑者に極端に集中するので、**レコードを増やしても異なり人数は早く頭打ちになる**。#245 は 300 件で 33 人を測っており、**倍に増やして 33 → 63 人**（＋30）である。

決定的なのは**確かめる術が無い**ことである。仮に 55,126 件すべてを引いて N 人が出たとしても、**N が 465 のうち何人を覆っているかは、正解の名簿が無いので検算できない**。名簿が無いことが問題なのに、検算に名簿が要る。**この経路は閉じない。**

## 4. 官報 → **robots.txt と利用規約の両方が禁じている。かつ 90 日で消える**

### 4-1. 本文の URL は全部 `Disallow` に当たる

`https://www.kanpo.go.jp/`（200 / 89,794 bytes）のリンクは**すべて日付ディレクトリ配下**である:

```
./20260828/20260828.fullcontents.html
./20260828/20260828h01778/20260828h017780000f.html
```

`robots.txt`（200 / 77 bytes）:

```
User-agent: *
Disallow: /20
Disallow: /old/

User-agent: ndl-japan
Disallow:
```

**`Disallow: /20` は上の日付ディレクトリすべてに一致する。** 過去分の置き場である `/old/`（`/old/index.html` は 200 だが中身は 55 bytes の `<meta http-equiv="refresh" content="0;URL=202606.html">` というリダイレクタだけ）も Disallow。**本文に到達する経路が全部塞がっている。** WARP と同じ形である。例外的に許可されているのは `ndl-japan` という特定のクローラ 1 つだけで、汎用の UA には開かれていない。

### 4-2. robots.txt だけでなく、規約が散文で禁じている

`https://www.kanpo.go.jp/guidance.html`（200 / 14,683 bytes）の「禁止事項」:

> 官報の安定した配信、正確な情報提供を行うため、**検索ロボットやクローラによるデータ収集等**の官報発行サイトに負荷をかける行為、不正アクセス等の官報発行サイトの運営を妨害する行為は**禁止します**。

**これは robots.txt の機械可読な意思表示と違い、散文で書かれた明示的な禁止である。** ETL は定義上クローラなので、**この一文だけで官報の経路は閉じる**。#245 が WARP について「取れるものが在るのに取らない」と書いたのと同じ判断を、ここでも採る。

### 4-3. そもそも過去回次は無料では読めない

同じページより:

> 発行から原則**90日間**は、官報全体を無料で閲覧・ダウンロードすることができます。

過去分として残るのは限定されている:

> 令和７年（2025年）３月31日までにインターネット版官報として配信された事項のうち、**平成15年（2003年）７月15日以降の法律、政令等**の官報情報と**平成28年（2016年）４月１日以降の政府調達**の官報情報を、PDFデータで閲覧することができます。

**残るのは「法律、政令等」と「政府調達」であって、議員の当選人の告示ではない。** つまり #316 が期待した「各回次の召集時の議員一覧」は、**仮に robots.txt と規約を無視しても、無料の範囲には存在しない**。

**官報の経路は三重に閉じている**（robots.txt / 規約の明文 / 90 日の壁）。**この経路に実装の余地は無い。**

### 5-3. 小選挙区の PDF は「読めるが、名簿の氏名と一致しない」

`000979134.pdf`（第50回）をテキスト抽出した結果、**289 件の `当` レコードが取れた**。これは第50回の小選挙区の議席数 289 と一致する。**抽出自体は成立している。**

問題は**氏名の種類**である。抽出したテキストの実物:

```

落 高　木　　ひろひさ 64 自由民主党 前 83,089    重 82.976
(高　木　　宏　壽)
```

- 行頭の `当`/`落`、**通称の氏名**（`高木ひろひさ`）、年齢、党派、新前元、職業、得票数
- 次の行の括弧内が**戸籍の氏名**（`高木宏壽`）
- その上の行の仮名（`たかぎ`）が**ふりがな**

**選挙資料の氏名は「投票用紙に書く通称」であって、名簿の氏名ではない。** これがどれだけ効くかを実測した。

| 突合の相手 | 一致数 | 率 |
|---|---|---|
| 通称の氏名（行頭 `当` のもの、289 件） | **80** | **27.7%** |
| 括弧内の戸籍の氏名（924 件、うち当落は区別せず） | **248** | — |

**同じ総選挙の当選者ですら、通称の氏名は 27.7% しか一致しない。** 一致しない例（実物）:

```

```

名簿側は `和田義明`・`宗清皇一` のような**漢字表記**である。**ひらがな交じりの通称と漢字の氏名は、文字列としては別物**で、正規化では吸収できない（`和田よしあき` → `和田義明` は変換ではなく**知識**である）。

括弧内の戸籍の氏名なら 248 件が一致するが、**括弧内の氏名は当落の印が付いた行とは別の行にあり**、しかも**2 段組のため 1 行に 2 人ぶんが混在する**。実測（第50回）:

| 項目 | 値 |
|---|---|
| `当`/`落` レコード | **1,113** |
| 括弧内の氏名 | **951**（レコードより **162 件少ない**） |
| 1 行に 2 レコードが載る行（2 段組） | **445** |
| 仮名だけの行（ふりがな） | **509** |

**レコード 1,113 に対し括弧内の氏名は 951 しか無い。** 通称と戸籍名が同じ候補者には括弧が付かないためだが、**どのレコードにどの括弧が対応するかは、テキスト抽出の行順からは決まらない**。実際に対応が壊れている例を抽出結果から挙げる:

```
落 宮　内　　し　お　り 32 日本共産党 新 委員会平和運動部 31,855    重 33.887 当 池　田　　まき 52 立憲民主党 元 政党役員 125,444    重 100.000
(松　村　　史　織) 長 (池　田　　真　紀)
```

**`宮内しおり` の下に括弧で付いているのは `松村史織`** である（`宮内しおり` の戸籍名ではなく、隣の段の別候補者のもの）。**2 段組の PDF をテキストに落とした時点で、氏名と括弧の対応も、氏名とふりがなの対応も壊れている。**

### 5-5. 465 人のうち何人に届くか（実測）

第51回の (13) から取れた**すべての氏名**（通称 + 括弧内の戸籍名）を集合にして、現在の名簿 465 人と突き合わせた:

## 6. 期間として確認する案が、形の問題を別にしても成立しない理由

#316 は自分でこう疑っている——**「補選・辞職・死去で入れ替わるので、期間だけでは足りない可能性がある」**。**この疑いは正しい。** 5 節の形の問題（PDF・通称・ふりがな）が仮にすべて解けたとしても、残る問題である。

総選挙の当選者は**「その総選挙の投票日に当選した 465 人」**という事実であって、**「第N回国会の会期中に議員だった人」ではない**。両者がずれる原因:

- **辞職・死去**（議員でなくなるが、当選者名簿からは消えない）
- **繰上補充**（名簿にいなかった人が議員になる）
- **補欠選挙**（総選挙の資料には載らない別の選挙）
- **会派の異動**（`MemberTerm.group` は名簿の列。**総選挙時の所属党派とは別物**で、`自由民主党・無所属の会` のような会派名は選挙資料に出てこない）

**総務省の資料に、任期中のこれらの異動を記録したものは無い**（`ichiran.html` にあるのは総選挙 8 回ぶんの結果調だけで、補選の結果は別の索引にあり、辞職・死去・繰上補充はそもそも選挙の資料ではない）。

したがって「総選挙から次の総選挙までを在職期間とみなす」は、**推定である**。#230 が 24,610 行を外し、#274 が「当選年から回次を決めるのは推定」として退けたのと**同じ種類の推定**であり、同じ理由で採れない。

**「期間として確認する」案は、資料の形の問題と、資料が記録している事実の種類の問題の、二重の意味で成立しない。**

## 7. `/coverage/` に書く文案

`apps/web/app/routes/coverage.tsx` の `ShugiinRosterSection`（「衆議院の記録が議員ページに紐づく範囲」）は、**既に「衆議院が公開している議員名簿は『現在』の 1 時点だけ」と書いている**。本調査が付け加えるべきは、**「衆議院のサイト以外の一次資料も探したうえで無い」**という事実である。#274 が参院について「**参議院のサイト以外の一次資料は調べていません**」と**主張の範囲を限定して**書いたのと対になる。今回は範囲を広げて調べたので、そう書ける。

**書き方の原則**（`coverage.tsx:249` のコメントのとおり）: 「活動がない」「発言していない」ではなく、**「収録した範囲に記録がない」**。

### 追記する段落（`ShugiinRosterSection` の 2 番目の段落のあと）

> 回次ごとの名簿にあたるものが**衆議院のサイト以外にもないか**を調べました。**国会会議録**には発言者の会派が記録されていますが、記録されるのは発言した人だけで、**その回次に議員だった人の一覧にはなりません**。**総選挙の結果**（総務省）には当選した人の氏名がありますが、**投票用紙に書く通称**で記載されており、議員名簿の氏名とは別の表記です（同じ総選挙の当選者で照合して、一致したのは 289 人中 80 人でした）。比例代表の当選者は、資料の形の都合で当選・落選の別を機械的に読み取れません。**官報**は、発行から 90 日を過ぎた過去の分が公開の対象外です。
>
> 総選挙の結果が使えたとしても、それは**その総選挙で当選した人**であって、**会期の途中の辞職・死去・補欠選挙・繰上補充は反映されません**。このサイトは、確認できないものを推測で補うことはしていません。調査の記録は
> [docs/research/shugiin-tenure-sessions.md](https://github.com/uonoko1/giinrecord/blob/main/docs/research/shugiin-tenure-sessions.md) にあります。

### 書かないこと（意図的に落とした）

- **robots.txt / 利用規約の話**（4 節）。**サイトの利用者に向けた情報ではない**。「取れなかった」ではなく「取ってよいと確認できなかった」という区別は開発上は重要だが、`/coverage/` は収録範囲を説明する場所なので、**結果だけを書く**。官報については「90 日を過ぎた分は公開の対象外」という**利用者から見て検証できる事実**だけを書いた
- **WARP**（#250 の回答待ち）。**状況が変わりうるものを収録範囲として断定しない**
- **「衆院議員は発言が第221回しかない」という言い方**。件数は同じ節の別の段落が `members/index.json` から数えて出しているので、**ここで回次や件数を重ねて書かない**（`coverage.tsx:130` の「連続収録と読ませない」の趣旨）
