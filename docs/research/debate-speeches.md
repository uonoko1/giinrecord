# 討論の登壇を種別として識別できるかの調査（Issue #243）

調査日: 2026-08-25。取得は国会会議録検索システム 検索用API `https://kokkai.ndl.go.jp/api/speech`、
UA `gikailog-etl/0.1 (+https://github.com/uonoko1/gikailog)`（`packages/etl/src/fetch.ts` の UA）、
**間隔 2.5 秒・逐次**（`NDL_API_INTERVAL_MS` = 2000 の下限を守った上で余裕を取った）。
取得結果はスクラッチ領域に置き、`data/` には**一切コミットしていない**。

#243 は「討論の登壇を個人の記録として収録する」ための PBI だった。
この調査の結論は **「討論」という種別は立てない**である。以下、実データで確かめた理由を書く。

## 結論（先に4行）

1. **`any=` は部分一致ではなく、索引は両方向に嘘をつく**。語順を入れ替えても 0 にならない一方、
   **`any=討論` が返したレコードの本文に「討論」が無い実例**（`122104889X01020260513_322`）がある。
2. **`speakerPosition` では議長・委員長を分離できない**。委員会の委員長は `speakerPosition` が `null` で
   `speakerGroup` を持ち、討論に登壇した議員と**フィールド上まったく区別が付かない**。
3. **文字列でも分離できない**。委員長が本会議で「委員会で討論が行われた」と報告する
   **委員長報告**は、討論者の「討論を行い**ます**」と**1文字違いの「討論を行い、」**で現れる。
4. **利用者が失うものは無い**。討論の登壇は #242 で既に `speech` 行として入っており、
   「反対の立場から討論を行います」は `excerpt`（原文冒頭200字）にそのまま入る。
   #243 が足そうとしていたのは「討論という種別ラベル」と「議案・立場の構造化」で、**その2つがどちらも推定**である。

---

## 1. `any=` の索引の性質（両方向に嘘をつく）

`any=` は本文の部分一致検索ではない。**語順を入れ替えても 0 にならない**（2026-08-25 取得、
`maximumRecords=1` の `numberOfRecords` を読んだ値）:

| クエリ | 院 | 回次 | `numberOfRecords` |
|---|---|---|---|
| `any=討論を行います` | 参議院 | 219 | 7 |
| `any=行います討論` | 参議院 | 219 | **1** |
| `any=を行います` | 参議院 | 219 | 198 |
| `any=行います討論` | 両院 | 221 | **1** |

逆向きにも嘘をつく。**`any=討論` で第221回に返った 563 件のうち 1 件は、本文に「討論」を含まない**:

```
speechID: 122104889X01020260513_322
衆議院 内閣委員会 第10号 2026-05-13  高山聡史（チームみらい）
本文: ○高山委員 ありがとうございます。 この後、今後も質疑が進んでいく中で是非伺っていきたいのは、
      その不断の見直しの部分でございまして、今回の法案の改正が、これまでの法案の運用の中で
      見つかった課題感であるとか、…
```

「党首討論」への言及ですらない、普通の質疑である。**索引の一致と本文の一致は別物**なので、
`any=` で拾ったものは**必ず本文を見て確かめる**必要がある。

### recall は測ったが、候補絞り以上には使えない

`any=` を使わずに ground truth を作って recall を測った。`from` / `until` で**日を指定して全発言を
無条件に取得**し（#263 と同じ方法。`any=` を介さない）、本文に「討論」を含む件数を数えて、
`any=討論`（第221回・両院）の結果集合と突き合わせた。

| 日 | 全発言（`speechOrder` ≠ 0） | 本文に「討論」を含む | `any=討論` の取りこぼし |
|---|---|---|---|
| 2026-07-16 | 1,191 | 33 | **0** |
| 2026-03-13 | 394 | 51 | **0** |

**この2日では recall 100%** だった。しかし上の「本文に無いものを返す」性質がある以上、
`any=` は**候補を絞る道具**であって、これで拾った集合を「討論の登壇」と断定する根拠にはならない。
（2日しか測っていない。全回次の recall は未測定。下記「見ていないこと」）

## 2. `speakerPosition` では議長・委員長を分離できない

「議事進行の発言は `speakerPosition` を持つので落とせる」という見込みは、**本会議の議長にしか当てはまらない**。

第221回・両院で数えた（2026-08-25 取得）:

| クエリ | 件数 | `speakerPosition` が非 null | `speakerGroup` が非 null |
|---|---|---|---|
| `any=討論を行います` | 116 | **0** | **116** |
| `any=これより討論に入ります`（＝明確な議事進行） | 64 | **0** | **64** |

**両方とも `speakerPosition` が全件 `null`、`speakerGroup` が全件あり**で、フィールドの形が同一である。
実例（2026-07-16、参議院。同じ会議・同じ日）:

```
松山政司  pos=null  grp=自由民主党・無所属の会
  「これより原案及び修正案について討論に入ります。御意見のある方は賛否を明らかにしてお述べ願います。」
  → 委員長の議事進行。本人は討論に立っていない

小池晃    pos=null  grp=日本共産党
  「私は、日本共産党を代表して、政府提出の皇室典範改定案に反対の討論を行います。」
  → 本人の討論
```

本会議の議長には `speakerPosition: 議長` が付く（`森英介`、2026-03-13 衆院本会議）が、
**委員会の委員長には付かない**。委員長は「その委員会の委員である議員」なので会派も持つ。
したがって `speakerPosition` / `speakerGroup` のどちらも、討論者と議事進行を分ける標識にならない。

## 3. 委員長報告 — 文字列でも分離できない（決定的）

`speakerPosition` が使えないなら本文の文字列で分けるほかないが、**それも成立しない**。

2026-03-13 衆議院本会議、**武村展英**（`speakerPosition: null` / `speakerGroup: 自由民主党・無所属の会`）:

```
ただいま議題となりました四法律案につきまして、財務金融委員会における審査の経過及び結果を
御報告申し上げます。…（中略）…次いで、四法律案について討論を行い、順次採決いたしましたところ、
特例公債法改正案及び所得税法等改正案は賛成多数をもって、復興財源確保法改正案及び…
```

これは**財務金融委員長が「委員会で討論が行われた」と本会議に報告している**のであって、
本人が賛否の立場で登壇したのではない。しかし文字列は「討論を行い、」で、
討論者の「討論を行い**ます**」と**1文字違い**である。

（同じ 2026-03-13 の会議録情報レコードで、武村展英が財務金融委員会の委員長であることが
出席者欄に明記されている。§7 参照。）

### 判定規則を2日の ground truth に当てた結果

「宣言パターン ∧ ¬議事進行パターン」の規則（宣言＝`討論を(行います|いたします|…)` / `(賛成|反対)の討論` 等、
議事進行＝`これより…討論に入ります` / `討論の通告があります` / `討論は終局` 等）を当てると:

| 日 | 本文に「討論」 | 登壇と判定 | 議事進行と判定 | **判定不能** |
|---|---|---|---|---|
| 2026-07-16 | 33 | 22 | 10 | **1** |
| 2026-03-13 | 51 | 26 | 17 | **8** |

判定不能 9 件の内訳（実物）:

- **委員長報告**（武村展英・坂本哲志・斎藤洋明）。上記のとおり両方のパターンに当たる、またはどちらにも当たらない
- **事務総長の議事説明**（築山信彦、`speakerPosition: 衆議院事務総長`）
  「次いで四人の方々からそれぞれ討論が行われますが、順序はお手元の委員会案件に記載のとおりでございます」
- **「討論が行われなかった」のに「討論」を含む**（國場幸之助・斎藤洋明）
  「これより討論に入るのでありますが、**その申出がありませんので**、直ちに採決に入ります」
- **「党首討論」への言及**（和田政宗・柴愼一）。討論の登壇とは無関係

正規表現を足せば個別には潰せる。しかしそれは**作った規則が今見た2日に合う**だけで、
**規則そのものが推定**である。作りの違う2日で既に 1件 / 8件 外しているものを、
22回次・全会議体（委員会・審査会・連合審査会・公聴会・調査会・分科会）に当てて
「これは討論の登壇である」と断定するのは、`docs/WORKING_AGREEMENT.md` の
**「実態より強い主張をしない」**に反する。

## 4. 立場（賛成／反対）は原文のまま以上に構造化できない

第221回の `any=討論を行います` 116 件について、「討論」宣言の直前 24 字を数えると
**85 種類**の表記があった（2026-08-25 取得の 116 件で計測）。

さらに**賛否が複合する**。実例:

```
原案に賛成、修正案に反対の立場から討論を行います                          （安達悠司・参政党）
原案に反対、修正案に賛成の立場から討論を行います                          （横山信一・公明党）
日・フィリピン、日・オランダ、日・ニュージーランド物品役務相互提供協定の承認にいずれも反対、
  日・カナダ刑事共助条約の承認に賛成の討論を行います                      （山添拓・日本共産党）
デジタル行政推進法等改正案に賛成、個人情報保護法等改正案に反対の立場から討論を行います
                                                                          （早稲田ゆき・中道改革連合）
```

これを 1 個の「賛成／反対」に潰すのは**推定**である。
`docs/research/individual-records.md` の 4-B が既に指摘していた点で、この調査でも同じ結論になった。

加えて、討論の多くは **「会派を代表して」**の発言である（上の実例のほとんどがそう）。
個人の行為として記録する意義は、この点で `stance`（衆院の会派態度＝推定）と同じ限界を持つ。

## 5. どの議案への討論かは特定できない

受け入れ条件にあった「議案」の紐づけは、発言レコードからはできない。

- 議案は本文中で**通称**として現れる（「国旗損壊処罰法案」「防衛省設置法等改定案」「再審法政府改定案」
  「皇室典範等改正案」）。`Bill.id` との対応表は無い
- **同日・同会議に複数の議案が乗る**実例がある。2026-07-16 の参院法務委員会は原案＋修正案、
  同日の参院外交防衛委員会は条約 4 件を一括して議題にしている
- 「原案」「修正案」は `bills/` に別のレコードとして存在しない

`packages/etl/src/sources/kokkai-attendance.ts` が参法の発議者で当たっているのと同じ問題である。
**紐づけるなら推定になる**ので、やらない。

## 6. 結論 — 種別は立てない。#242 で原文として既に入っている

**「討論」という `TimelineEntry` の種別は立てない。**

重要なのは、**討論の登壇は #242（委員会の発言を収録）で既に議員の記録として入っている**ことである。
第221回の `any=討論を行います` 116 件は**全件が `speakerGroup` を持つ**ので、
`matchSpeeches` で名簿に突合され、`speech` 行として `members/{id}/speeches.json` に入る。
`excerpt`（原文冒頭 200 字）には「反対の立場から討論を行います」が**原文のまま**入り、
議員ページの発言タブに**会議名・日付・一次資料リンク付き**で出る。

#243 の受け入れ条件と照らすと:

| 受け入れ条件 | 状態 |
|---|---|
| 日付・会議名・一次資料リンク | **#242 で満たしている** |
| 立場は原文の表記をそのまま。丸めない・解釈しない | **#242 で満たしている**（`excerpt` が原文） |
| 議員ページに出る | **#242 で満たしている**（発言タブ） |
| 会派の態度（推定）と明確に区別 | **#242 で満たしている**（`speech` は事実、`stance` は推定） |
| 議案の紐づけ | **できない**（§5） |
| 討論という種別ラベル | **推定になる**（§2・§3） |

**利用者が失うものは無い。推定のラベルを足さない、という判断である。**
#245 で WARP を「取得しない」と決めたのと同じ形。

第221回の内訳（参考。`any=討論を行います` の 116 件、2026-08-25 取得。
§1 のとおりこの数字は「索引が返した件数」であって「討論の登壇の全件」ではない）:
参議院 63・衆議院 53、委員会等 83・本会議 33。

## 7. `speechOrder: 0`（会議録情報）について — #244 に効く知見

#244（委員会の構成・委員長・理事）の担当に渡す知見。この調査の副産物である。

**出席者欄の「委員長」は、その会議の議事進行の発言者と一致する。** 2 日ぶんで確かめた
（`issueID` で同じ会議録に絞り、議事進行の語を含む発言の話者と、`speechOrder` 0 の出席者欄の
委員長名を突き合わせた）:

| 日 | 会議録情報レコード | 出席者欄の委員長＝議事進行の発言者 |
|---|---|---|
| 2026-07-16 | 9 | 8 会議で一致（憲法審査会は「委員長」の語が無く `会長`） |
| 2026-03-13 | 7 | 6 会議で一致（**本会議を除く**） |

**注意すべき例外が 2 つある**:

1. **本会議の会議録情報の出席者欄に載る「委員長」は、その本会議を仕切る議長ではない**。
   2026-03-13 の衆院本会議では、出席者欄から取れる委員長は `坂本哲志`（予算委員長）だが、
   実際に議事進行をしたのは `森英介`（`speakerPosition: 議長`）である。
   **本会議の出席者欄は「出席した国務大臣・委員長」を載せる**ので、
   ここから「議長」を作ると誤る。
2. **審査会は「委員長」ではなく「会長」**（憲法審査会 2026-07-16 は `古屋圭司` が議事進行をしているが、
   `委員長\s*([^\s君]+)君` の正規表現では取れなかった）。会議体ごとに役職名が違う。

また §3 の委員長報告は、**出席者欄から「武村展英＝財務金融委員長」が事実として取れる**ことと
表裏である（2026-03-13 の財務金融委員会 第5号の会議録情報に載る）。
**役職は会議録情報に原文で明記されるので事実として取れる**——これは §2 で
「発言レコードからは役職が分からない」と言ったのと矛盾しない。**別のレコードに載っている**。

## 見ていないこと

- **recall を 2 日ぶんしか測っていない**（2026-07-16・2026-03-13）。他の日・他の回次で
  `any=` が取りこぼすかは未測定。§1 の「100%」はこの 2 日の値である
- **第221回以外で「討論」の表記を数えていない**。85 種類・複合の実例は第221回の 116 件で数えた値
- **判定規則を全回次に当てていない**。判定不能 1件 / 8件 は 2 日の ground truth に対する値で、
  全体の誤り率ではない。そもそも規則を採らない結論なので測っていない
- **`122104889X01020260513_322` がなぜ `any=討論` で返るのか**は分からない。
  索引の作り方は API の仕様として公開されていない。**現象として記録するにとどめる**
- **同姓同名の討論者**。討論は `speakerGroup` を全件持つので `resolveMember` は会派で絞れるが、
  同姓同名かつ同会派の例があるかは調べていない
- **`speechOrder` 0 の出席者欄と議事進行の突合を 2 日（16 会議）でしか確かめていない**（§7）。
  参院・衆院で 1 日ずつなので、会議体ごとの役職名の揺れ（`会長` 以外）は網羅していない
