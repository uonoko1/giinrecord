# 個人の行為として一次資料に残るものの調査（Issue #237）

調査日: 2026-08-24。取得は `curl -A "gikailog-etl/0.1 (+https://github.com/uonoko1/gikailog)"`（`packages/etl/src/fetch.ts` の UA）、間隔 ≥ 1.2 秒、計 22 リクエスト。
robots.txt は `kokkai.ndl.go.jp` が 302（実体なし）、`www.shugiin.go.jp` が 404（実体なし）。どちらも禁止の記載は無い。

## いま何が足りないか（現状の実測）

`data/members/` の衆院議員 465 人の timeline を数えると、

| 種類 | 行数 | 割合 |
|---|---|---|
| `stance`（会派態度＝**推定**） | 47,867 | 97.2% |
| `bill`（提出者・賛成者＝事実） | 1,353 | 2.7% |
| `speech` / `vote` / `question` | 0 | 0% |

**465 人のうち 195 人は timeline が会派態度 100%**（個人の行為が 1 行も無い）。
参院側は 60 人サンプルで `vote` 19,542・`speech` 1,746・`question` 126・`bill` 70・`attendance` 3 と、事実の行がある。
衆院議員のページが「会派の態度（推定）で埋まる」のは、この差がそのまま出たもの。

以下、埋められる一次資料を 4 項目で調べた。

---

## 1. 委員会での発言

### 一次資料と取得可否

国会会議録検索システム 検索用API `https://kokkai.ndl.go.jp/api/speech`。**取得可**。
現在の実装（`packages/etl/src/sources/kokkai-speeches.ts`）は `nameOfMeeting=本会議` で固定していて、**このパラメータを外すだけで委員会・審査会・分科会の会議録が同じ形で返る**。

### 量（第221回、実測）

| 院 | `nameOfMeeting=本会議` | 指定なし（全会議） | 倍率 |
|---|---|---|---|
| 衆議院 | 919 | 33,313 | **36.2 倍** |
| 参議院 | 544 | 36,550 | **67.2 倍** |

両院の本会議以外は 68,400 件（33,313−919 ＋ 36,550−544）。

### 個人への紐づけ

**可能。本会議と全く同じ**。委員会レコードも `speaker` / `speakerGroup` / `speakerPosition` / `speakerYomi` を持つ（フィールド構成は本会議と同一。`speakerRole` という未使用フィールドもあるが、見た 300 件では全て `null`）。

```
122105261X01720260727_001  予算委員会 第17号 2026-07-27
speaker: 坂本哲志  speakerGroup: 自由民主党・無所属の会  speakerPosition: null
```

ただし委員会には**議員でない発言者（政府参考人・局長・参考人）が混ざる**。3 か所のサンプル 298 件で `speakerGroup` を持つ（＝会派所属＝議員）のは 250 件（84%）。

- 予算委員会（総理入り）100 件中 96 件が会派あり
- 総務委員会・災害対策特別委員会 99 件中 63 件（`遠藤剛`・`湯本博信` 等の政府参考人が 36 件）
- 予算委員会 別日 100 件中 91 件

`speakerGroup` の有無は「議員かどうか」の代理指標として使えるが、**それ自体は判定ではない**。既存の `matchSpeeches`（氏名＋会派で名簿に突合）を通せば、名簿に無い政府参考人は自然に落ちる。推定は増えない。

### 日次 ETL への影響（見積り）

日次 ETL は `targets`（＝現行回次）だけ取得して過去回次は `data/` から引き継ぐ（`cli.ts` L92 以降）ので、**日次の増分は 1 回次ぶん**。

| 指標 | 現状（本会議のみ） | 委員会を足したとき |
|---|---|---|
| API ページ数（100件/ページ、両院1回次） | 15 ページ | **700 ページ** |
| 所要時間（`REQUEST_INTERVAL_MS`=1000 を守る） | 約 15 秒 | **約 12 分** |
| 追加 timeline 行（84%が議員として） | — | 約 57,000 行/回次 |
| 追加サイズ（既存 speech 行の実測平均 819 バイト） | — | **約 45 MB/回次** |

`data/members/` は現在 84 MB。**1 回次で 1.5 倍になる**。回次を重ねると線形に増える。

対策の候補（実装時に決める。この調査では結論を出さない）:
- `EXCERPT_CHARS`（現在 200）を委員会発言だけ短くする
- 会派を持つ発言（＝議員）だけ保存する
- timeline には出さず件数と代表数件だけ持つ

### 実装難度・リスク

**低い**。`speechPageUrl` から `nameOfMeeting` を外し、`Speech.meeting` は既に「会議名＋号」を入れているので表示側の変更もほぼ無い。
リスクは**量だけ**（サイズ・所要時間・GitHub のリポジトリ肥大）。衆院側は名簿が現行回次しか無いので、名寄せできるのも現行回次だけ（項目 2 と同じ制約）。

## 2. 法案の賛同者（賛成者）— 「賛同法案 0」の原因

### ログの数字の内訳（`data/bills/` 1,941 件の実測）

ETL ログ `1941 total, 540 with submitter/supporter names, 39 linked to roster members` の中身は、

| | 件数 |
|---|---|
| 議案ファイル総数 | 1,941 |
| `submitterNames`（提出者の氏名）を持つ | **540** |
| `supporterNames`（賛成者の氏名）を持つ | **420** |
| `submitters`（memberId に紐づいた）を持つ | 39 |
| `supporters`（memberId に紐づいた）を持つ | **29** |

**賛成者名は 540 件中 420 件が既に取れている**（衆法は 493 件すべてが `submitterNames` を持つ。氏名の欄が無い議案＝閣法・参法・予算・条約を除いた分がこの 540）。
回次別に見ると `submitterNames` は第195回〜第221回の 23 回次に分布しているのに、**`submitters` が付いているのは第221回の 39 件だけ、`supporters` は第221回の 29 件だけ**。

### なぜ 39 件しか紐づかないか

**スクレイピングの失敗ではない。名簿が「現在」の 1 回次分しか無いから**。

`packages/etl/src/match-shugiin-bills.ts` は `rosterCoveredSessions()` で名簿の `terms[].sessionFrom..sessionTo` が覆う回次だけ名寄せする。衆院名簿の取得元

`https://www.shugiin.go.jp/internet/itdb_annai.nsf/html/statics/syu/1giin.htm`

は先頭に **`令和8年2月18日現在`** と書かれた**現時点のスナップショット 1 枚**で、回次ごとの過去名簿は無い（`1giin_g.htm` は 404）。そのため衆院議員の `terms` は全員 `sessionFrom: 221`（実物: 古川元久 `[{"district":"愛知2","group":"国民民主党・無所属クラブ","sessionFrom":221,"timesElected":11}]`）。覆う回次は 221 のみ。

これは意図された挙動で、`match-shugiin-bills.ts` のコメントが理由を書いている:

> 衆院は「現在」の名簿しか無い（Issue #71）ので、過去回次の議案の氏名は、今の名簿に無いのが正常でも無いのが誤りでも区別できない。名簿の無い回次と同じ扱いにして推測も確認表の汚染も避ける。

つまり**一次資料側は既に揃っていて、足りないのは回次ごとの衆院名簿だけ**。

### 一次資料の確認（実物を見た）

`https://www.shugiin.go.jp/internet/itdb_gian.nsf/html/gian/keika/1DDF116.htm`（第217回 決議1、Shift_JIS）

```
議案提出者一覧  森山裕君; 坂本哲志君; 宮下一郎君; 簗和生君; 鈴木貴子君; 加藤鮎子君; …（22名）
議案提出の賛成者  黄川田仁志君; 三反園訓君; 中野英幸君; 福田かおる君; 平井卓也君; …（46名）
```

提出者 22 名・賛成者 46 名の氏名が全員載っている。`data/bills/217/217-決議-1.json` はこの 68 名を `submitterNames` / `supporterNames` として既に保持していて、`submitters` / `supporters` だけが空。

### 個人への紐づけ可否

**回次ごとの衆院名簿があれば事実として紐づく**（氏名は原文に全員分ある。推定は要らない）。
名簿が無いまま氏名一致だけで現職に紐づけるのは**推定**なので、やらない（`docs/research/backfill-142-199.md` が参院で出したのと同じ結論）。

### 実装難度・リスク

議案側の実装は**ゼロ**（データは既にある）。難度は**回次ごとの衆院名簿を作れるか**に完全に依存する。
候補の資料は項目 4-A の委員会会議録 冒頭情報（`出席委員` 欄）だが、**出席者は在籍者の一部でしかない**（`backfill-142-199.md` が「会議録 API から在籍者名簿を組み立てること」をスコープ外にしたのと同じ問題）。この調査の範囲では、**過去回次の衆院名簿を作る一次資料は見つかっていない**（下の「見ていないこと」に記載）。

一方で**第221回（現行回次）については既に 39 件動いている**ので、日々の運用では回次が進むたびに 1 回次ぶんずつ積み上がる。

## 3. 委員会での採決

### 結論: **個人名の残る委員会採決の記録は無い**（衆参とも）

#### 参議院

個人別投票の一覧 `https://www.sangiin.go.jp/japanese/touhyoulist/221/vote_ind.htm` を取得。
掲載されている案件は**すべて本会議のもの**（`日程第１　国家公務員等の任命に関する件…` 等）で、委員会の採決は 1 件も無い。ページ内の「委員会」の出現 10 件はすべて案件名の中（`公害等調整委員会委員（横田信孝君）` のような人事案件）で、会議名ではない。

#### 会議録の本文（両院・第221回）

- `any=記名投票` で第210〜221回を検索 → 80 件。上位はすべて**本会議の議長発言**（`表決は記名投票をもって行います`）か、**議院運営委員会で本会議の採決方法を決める発言**（`なお、本決議案の採決は、記名投票をもって行います`）。委員会自身を記名投票で採決した記録は見ていない。
- `any=起立`（衆議院・第221回）→ 468 件。委員会・本会議とも採決の記載は

```
○議長（森英介君）　…賛成の諸君の起立を求めます。
　　　　〔賛成者起立〕
○議長（森英介君）　起立多数。よって、そのとおり決しました。
```

**`〔賛成者起立〕` と `起立多数` だけで、誰が起立したかの氏名は無い**。委員会採決も同じ形式。

### 実装可否

**不可**。一次資料が存在しない。会派態度から個人の賛否を作らない現行方針（`DATA_CONTRACT.md`）はここでも変えない。

## 4. その他の個人の行為

### 4-A. 委員会の構成（委員長・理事・委員）と委員の異動 — **取得可、事実**

会議録 API の `speaker=会議録情報`（`speechOrder` 0）のレコード本文に、その日の**出席委員の氏名と役職**が入る。
現在の `parseSpeechPage` は `speechOrder === 0` を捨てているので未利用。`packages/etl/src/sources/kokkai-attendance.ts` が同じレコードを参院の「発議者」抽出に使っているので、**パース基盤は既にある**。

参議院（`予算委員会 第17号` 2026-07-24）は 1 行 1 名で役職見出しが明示的:

```
　　出席者は左のとおり。
　　　　委員長　　　　　　　　　藤川　政人君
　　　　理　事
　　　　　　　　　　　　　　　　阿達　雅志君
　　　　　　　　　　　　　　　　加藤　明良君
　　　　委　員
　　　　　　　　　　　　　　　　朝日健太郎君
```

衆議院（`内閣委員会 第29号` 2025-06-20）は 1 行 2 名の 2 段組:

```
　出席委員
　　　委員長　大岡　敏孝君
　　　理事　黄川田仁志君　理事　國場幸之助君
　　　　　　石原　宏高君　　　　井野　俊郎君
```

同じレコードに **`委員の異動`**（`辞任 水沼秀幸君 → 補欠選任 野間健君`）も入る。

量（実測）: 第221回の `会議録情報` レコードは**衆議院 344・参議院 318**（＝開会日数×会議体）。衆院 100 件のサンプルでは 85 件に出席者欄、72 件に `委員の異動` があり、1 回あたりの出席者名は平均 30 名・中央値 30 名。100 回ぶんで延べ 323 の異なる氏名（衆院議員 465 人の 7 割）が現れた。

紐づけ: **氏名は事実として載る**。ただし会議録に会派は書かれないので、同姓同名は絞れない（`resolveMember` に会派を渡せない＝`match-shugiin-bills.ts` と同じ条件）。

実装上の注意（実際に躓いた）: 素朴な `([^\s]{2,12})君` の正規表現は `こう`・`りえ`・`一基` のような**姓名の断片を拾う**（全角スペースが姓名の区切りにも段組の区切りにも使われるため）。院ごとに別のパーサが要る。

**「委員長を務めた」「理事だった」は会派ではなく個人の役職**で、いまリポジトリに全く無い種類の記録。

### 4-B. 討論（賛成討論・反対討論）— **取得可、事実だが要注意**

会議録 API。第221回を `any=討論を行います` で検索 → **113 件**（サンプル 100 件の内訳: 参議院 60・衆議院 40、**委員会等 76・本会議 24**）。100 件すべてに `speakerGroup` があり（＝全員議員）、氏名で個人に紐づく。

```
憲法審査会 第10号 2026-06-18  畑野君枝（日本共産党）
「私は、日本共産党を代表して、国民投票法改定案に反対の討論を行います。」

内閣委員会 第18号 2026-06-10  塩川鉄也（日本共産党）
「私は、日本共産党を代表して、宇宙活動法改正案に対し、反対の討論を行います。」
```

**「その議員がその議案に賛成／反対の立場で登壇した」という、会派態度ではない個人の行為**。衆院議員に足りないものにいちばん直接効く。

ただし**賛否の機械抽出には落とし穴がある**:

- 表現がぶれる。`（賛成|反対）の討論` の正規表現は 100 件中 33 件しか当たらない。`反対の立場から討論を行います`・`断固反対の立場から` まで含めた広めの正規表現で 93 件。残り 7 件は未確認。
- **賛否が複合する**。実例:
  - `原案に賛成、修正案に反対の立場から討論を行います`（安達悠司）
  - `原案に反対、修正案に賛成の立場から討論を行います`（横山信一）
  - `皇室典範等改正案原案、修正案に対し、反対の立場から`（伊勢崎賢治）

  これを 1 個の「賛成／反対」に潰すのは**推定**。
- どの議案への討論かは発言文中の議案名で示され、`Bill.id` との対応は自明ではない（会議録情報の「本日の会議に付した案件」と突き合わせる必要があり、同日に複数議案があると特定できない場合がある。`kokkai-attendance.ts` が参法で同じ問題に当たっている）。

**安全な採り方**: 「討論に立った」という事実（議員・日付・会議名・冒頭抜粋・原文 URL）だけを記録し、賛否と議案 ID は原文の抜粋に語らせる。賛否ラベルを付けるなら「原文にこう書いてある」以上には踏み込まない。

### 4-C. 請願の紹介議員 — **取得可、事実、量が多い**

請願は議員 1 人の紹介がないと提出できないので、**`（○○君紹介）` は完全に個人の行為**。

会議録 API の `会議録情報` レコード本文に載る:

```
　日本軍慰安婦問題の解決に関する請願（伊藤俊輔君紹介）（第二九七七号）
　公務・公共サービスの拡充に関する請願（青山大人君紹介）（第二九七八号）
　同（赤嶺政賢君紹介）（第二九七九号）
```

量（実測）: 衆議院・第221回の `会議録情報` 100 件で **1,653 件の紹介記載、192 人の異なる議員名**。厚生労働委員会だけで 1,357 件と偏りが大きい。

`（○○君紹介）` の正規表現は姓名がまとまって入るので 4-A の出席者欄より**抽出しやすい**。ただし `同（赤嶺政賢君紹介）` の `同` は直前の件名を指す前方参照なので、件名を持たせるなら直前行を引き継ぐ処理が要る。

**衆参の公式請願ページには紹介議員名が無い**（確認済み）:
- 衆議院 `https://www.shugiin.go.jp/internet/itdb_seigan.nsf/html/seigan/menu.htm` は委員会別の「新件番号／請願件名」の 2 列だけ。紹介議員の列は無い。回次別 URL `kaiji221.htm` は 404。
- 参議院 `https://www.sangiin.go.jp/japanese/joho1/kousei/seigan/221/seigan.htm` はページ全体で「紹介」の出現が **0 件**。件名ごとの詳細ページへのリンクも無い。

よって**紹介議員名の一次資料は会議録だけ**。

### 4-D. 議員立法の発議者・提出者 — **既に実装済み**

衆法は `議案提出者一覧`（項目 2）。参法の発議者は `docs/research/sangiin-cosponsors.md` の結論のとおり**筆頭者しか公表されていない**ので増やせない。委員会出席の発議者は `kokkai-attendance.ts` で `attendance` 行として実装済み。**この項目に新規の一次資料は見つからなかった**。

### 4-E. 質疑者 — **4-A/4-B と同じ資料**

「質疑に立った」は委員会発言（項目 1）そのもの。項目 1 を入れれば別立ての実装は要らない。会議録の本文から「質疑」だけを選り分ける確実な標識は探していない（下記「見ていないこと」）。

## 実装 PBI の案と優先順位

費用対効果は「衆院議員 465 人（うち 195 人は個人の記録ゼロ）の timeline に事実の行がどれだけ増えるか」÷「実装・運用コスト」で見た。

| 順 | PBI 案 | 増える記録 | コスト | 根拠 |
|---|---|---|---|---|
| **1** | **委員会発言を取り込む（項目 1）** | 1 回次あたり両院で約 57,000 行。**衆院議員のほぼ全員に初めて `speech` 行が付く** | 実装 小（`nameOfMeeting` を外す）／**運用 大**（+45 MB・+12 分/回次） | 効果が桁違いに大きく、実装が最小。ただし保存方針（抜粋長・会派なし発言の扱い）を PBI 内で決める必要がある。**サイズ対策とセットで 1 本の PBI にする** |
