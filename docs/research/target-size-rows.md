# 一覧の行の中のリンクと WCAG 2.5.8（Target Size (Minimum)）

Issue #424（#413 の第3段階）の判断の記録。
**次に測る人が同じ判断を繰り返さないために残している。**

結論を先に書く: **対象の 49 箇所は 1 箇所も直していない。全部が Spacing 例外に当たる。**

散文の中のリンク（#425）についての同じ形の記録は `docs/research/target-size-inline.md` にある。
判断の基準（Understanding 文書の引用）はそちらに詳しいので、ここでは**この 49 箇所の実測**を残す。

---

## 1. なぜ「小さい」だけでは違反にならないのか

[Understanding SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) の
**Spacing 例外**（原文）:

> Undersized targets (those less than 24 by 24 CSS pixels) are positioned so that if a 24 CSS
> pixel diameter circle is centered on the bounding box of each, the circles do not intersect
> another target or the circle for another undersized target.

24px 直径の円を各ターゲットの bounding box の中心に置いて、円同士が重ならなければ合格。
言い換えると**隣のターゲットの中心までが 24px 以上あればよい**。
これは大きさではなく**間隔**の基準なので、**行の高さを一切変えずに満たせる**。

> ### 「24×24 未満 = 違反」ではない
> 押し間違いが起きるのは「小さい」からではなく「小さくて**密集している**」からである。
> #413 が数えた 110 箇所は「24×24 未満の数」であって、**違反の数ではない**。
> この Issue #424 の 49 箇所も、**数えた時点では違反かどうか判定されていなかった**。

## 2. 測り方

`pnpm build` した成果物を静的に配信し（`vite preview` は SPA フォールバックを返すので使えない）、
Playwright の Chromium を **390px 幅**で開いて `getBoundingClientRect()` を読んだ。

判定に使った値は 2 つ。

1. **大きさ** — 24×24 CSS px 未満か
2. **最も近いターゲットの中心までの距離** — Spacing 例外の判定。
   ターゲットは `a[href], button, input, select, textarea, [role="button"], [tabindex]:not([tabindex="-1"])` とした。

### 測るときの落とし穴（実際に踏んだ）

- **`document.fonts.ready` だけでは足りない。** 読み込み中のフォントが無くなるまで待ち、
  さらに 1.5 秒待って 3 回同じ値が出ることを確かめた。待たずに測ると代替フォントの高さになる。
- **`` `${".a, .b"} a` `` は壊れる。** カンマ区切りの選択子に後ろから ` a` を付けると
  **最後の項にしか掛からない**（`.row, .rollcalls-item, .list__item a` になる）。
  この書き方をしていた最初の計測は「24px 未満 0 箇所」という**嘘の合格**を出した。
  各項に配ってから `join(", ")` すること。

再現に使ったスクリプトはこの PR には入れていない（一時ファイル）。上の 2 つの値さえ取れば同じ判断ができる。

## 3. 対象 49 箇所の表

「間隔」= 最も近いターゲットの中心までの距離。**24 以上なら Spacing 例外に当たる。**

| ページ | 要素 | 件数 | 大きさ | 間隔 | 判断 |
|---|---|---:|---|---:|---|
| `/` | `.row a`（出典と更新） | 27 | 134〜191×13 | **30** | 例外（Spacing） |
| `/rollcalls` | `.rollcalls-item a` | 13 | 350×21.75 | 62.75 | 例外（Spacing） |
| `/assemblies` | `.list__item a` | 9 | 350×21 | 58 | 例外（Spacing） |

**合計 49 箇所。直したものは 0 件。Spacing 例外を満たさないものは 0 件。**

`/rollcalls/221` にも `.rollcalls-item` の小さいリンクが 9 箇所あるが、`/rollcalls` と同じ
コンポーネント・同じ CSS なので件数には数えていない（間隔も同じ 62.75px）。

### 間隔の最小値は `/` の「出典と更新」の 30px

一番余裕が無いのは `/` の `.row`（出典と更新）で、縦に並ぶリンクの**中心間が 30px**。
必要な 24px に対して**余裕は 6px しかない**。ここが**このページで最初に壊れる場所**である。

内訳: `.row` の高さ 30px = `padding: 8px 0`（上下 16px）+ 文字 13px（`line-height: normal`。
このフォントでの実測は 1.0 で、13px がそのまま行の高さになる）+ 端数。

**webfont が落ちた状態（代替フォント）でも測った**: 文字が 18px に増えるので間隔は **35px** に広がる。
つまりフォントの読み込み状態に関わらず 24px を下回らない。

## 4. なぜ「行の中のリンク」を大きくしないのか

`.row` は `/` で縦に密に並ぶので、#424 は「押し間違いが起きやすい配置」を心配していた。
しかし**実測した間隔は 30px あり、Spacing 例外を満たしている**。

このブランチには一度
`padding-block: 6px; margin-block: -6px`（padding で押せる範囲を広げ、同じ量の負の margin で
行の高さを戻す）を入れて、49 箇所すべてを 25px 以上にした実装があった。**それは revert した。**
測った結果、**得るものが無いまま副作用だけが残る**と分かったからである。

- **当たり判定と見た目がずれる。** 負の margin で押し戻すぶん、
  隣の行の文字の上に不可視の当たり判定が 6px かぶさる。
  実際、この実装を入れた状態で `.rows` の**隣り合うリンクの箱のすき間は 17px → 5px** に縮んだ。
  「文字を押したのに上の行のリンクが開く」は、**今より悪い**。
- **達成基準はもう満たしている。** 2.5.8 は「独立した操作要素は 24px でなければならない」とは書いていない。
  Spacing 例外を満たせば合格である。
- 基準のためではなく「数字を 24 にするため」の指定は、次に触る人に
  「これは必要な指定だ」と誤解させる。

**「24×24 未満だから直す」ではなく「例外に当たらないから直す」で判断すること。**

---

## 5. この判断が変わる条件

次のどれかが起きたら測り直すこと。**`/` の `.row` は余裕が 6px しか無い。**

- **`.row` の `padding: 8px 0` を詰めた**とき。上下あわせて 6px 以上詰めると
  中心間が 24px を割り、**Spacing 例外を外れて本当に違反になる**。
  `.rows` の `font-size: 13px` を小さくした場合も同じ。
- **`.row` の中にリンクを 2 つ以上置いた**とき。いまは 1 行に `a` が 1 つ（右は `span` で非ターゲット）。
  横に並べると円が横方向で重なりうる。
- **`.rollcalls-item` / `.list__item` の `padding`（12px / 10px）を大きく詰めた**とき。
  こちらは間隔 58〜62.75px で余裕があるが、半分以下にすると危うい。
