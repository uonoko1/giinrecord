## 2. なぜ落ちるのか——**`tenureVerified` で確定している**（変異で確認）

落ちている場所は `packages/etl/src/match-votes.ts:140`。

```ts
export function resolveMember(index: NameIndex, nameText: string, group: string | undefined, at?: RecordAt): Member | undefined {
  const named = index.get(normalizeName(nameText)) ?? [];
  const candidates = at === undefined ? [] : named.filter((m) => tenureVerified(m, at));  // ← ここで 229 件が消える
```

`tenureVerified`（`:110`）は (a) `rosterCovers`（`:115`）か (b) `tenureCarriedOver`（`:120`）のどちらかを要求する。
**衆院議員については、どちらも成立しえない。**

- **(a) が成立しない**: 衆院名簿は回次ごとの公開が無く「現在」の 1 回次分しか無い（#71）。
  `data/members/` の **衆院 term 465 件はすべて `sessionFrom: 221` / `sessionTo` 無し**である
  （`sessionTo ?? sessionFrom` = 221）。**第217回・第219回は覆われない。**
  出典は `packages/etl/src/sources/shugiin-members.ts:84` の `sessionFrom: session`（`session` は `memberSession` = 221）。
- **(b) が成立しない**: `tenureCarriedOver` は `t.to`（任期満了日）を要求するが、
  **衆院 term 465 件のうち `to` を持つものは 0 件**である（参院は 383 / 383 が持つ）。
  `shugiin-members.ts:84` は `from: ""` を入れるだけで `to` を入れない。
  **したがって `date` を渡しても (b) は衆院議員には一度も効かない。**

### 変異で確かめた（`scripts/dev/mutate.sh`）

**予測を先に書いてから当てた。**

| 変異 | 予測 | 実測 |
|---|---|---|
| **`tenureVerified` を `return true;` にする** | 229 件が突合し、A の 72 件だけが残る | **突合 229 / 未突合 72**（予測どおり） |
| **`rosterCovers` の上限を外す**（`sessionFrom <= session` だけにする） | 落ちているのは**下限**（221 > 217）なので救われない＝突合 0 のまま | **突合 0 / 未突合 301**（予測どおり） |

2 つ目が要点である。**「名簿の回次が発言より新しい」を直すのに `sessionTo` 側をいじっても 1 件も戻らない。**
`sessionFrom` が 221 で発言が 217 という**下限**が原因である。

### 反実仮想（メモリ上の名簿コピーで測定。`data/` は書き換えていない）

| 衆院 term の `sessionFrom` を 217 に下げる（`sessionTo` は無いまま） | 198 | 103 |
| 衆院 term を `sessionFrom: 217, sessionTo: 221` にする | **229** | **72** |
| 会派を空文字にして引く（`group: ""`） | 0 | 301 |

- **2 行目が 229 でなく 198 なのは `sessionTo ?? sessionFrom` のため**。`sessionTo` が無いと覆う範囲は 217 の 1 点だけになり、
  第219回の 31 件が救われない。**「`sessionFrom` を下げる」だけでは足りない。**
- **4 行目**: 会派を空にしても未突合は 301 のまま＝**会派で 1 人に絞れずに落ちた行は 0 件**。
  同姓同名による取りこぼしはこの 301 件には含まれない。

Issue 本文は「重徳和彦・青柳仁士・田中健ほか **11 人以上**が `terms[].sessionFrom` が `""`」としていた。

## 3. なぜ第217回と第219回だけなのか

**`meta.json` の `sessions` は 200〜221 の 22 会期あるが、発言を取得しているのは 216〜221 の 6 会期だけである。**
そして **301 件はすべて参議院の会議録の発言**である——**「衆院の発言」というのは発言者の院であって、会議の院ではない。**

`speechId`（NDL の `speechID`）の 5 文字目が会議の院で、`0` = 衆議院・`1` = 参議院である
（公開済み発言 94,421 件で照合: `d4=0` は衆院議員 26,388 / 参院議員 815、`d4=1` は衆院議員 6,561 / 参院議員 60,657。
**院をまたぐ発言者がいるので 100% にはならないが、多数側が会議の院であることは明らか**）。
**`data/unmatched.json` の 301 件は 301 件すべてが `d4=1`（参議院の会議録）である。**

### 公開済み発言を「会議の院 × 回次 × 発言者の院」で数えた

| 回次 | 参院会議・発言者=参院 | 参院会議・発言者=衆院 | 衆院会議 |
|---|---:|---:|---:|
| 216 | 4,258 | **0** | 0 |
| 217 | 25,533 | **0** | 0 |
| 218 | 477 | **0** | 0 |
| 219 | 5,684 | **0** | 0 |
| 220 | 181 | **0** | 0 |
| **221** | 24,524 | **6,561** | 27,203 |

**第216〜220回は、参院の会議に出た衆院議員の発言が 1 件も突合していない**（衆院名簿が 221 しか覆わないため）。
**第221回だけ 6,561 件が突合している**のは、名簿が第221回を覆うからである。

**衆院の会議録は第221回しか取得していない**（`cli.ts:256` の `fetchSpeeches(memberSession, "shugiin", …)`。
`memberSession` = `Math.max(...plan.all)` = 221）。**だから衆院会議の行が 0 の回次がある。**
この範囲は `DATA_CONTRACT.md:231` に「名簿が覆う回次しか突合できないので過去回次は取らない」と書かれている設計どおり。

### **では 216 / 218 / 220 に unmatched が 0 なのはなぜか**

**同じ機序は 216・218・220 でも働くはずである。0 なのは、機序が無いからではなく、
その回次の参院会議に衆院議員が（`position` を持たない発言者として）出ていないからと読める。**

観測できる母数:

```
第216回 参院会議 4,258 件（unmatched 0）
第217回 参院会議 25,533 件（unmatched 251）→ 観測母数 25,784、unmatched 率 0.97%
第218回 参院会議   477 件（unmatched 0）
第219回 参院会議 5,684 件（unmatched 50）→ 観測母数 5,734、unmatched 率 0.87%
第220回 参院会議   181 件（unmatched 0）
```

**第218回（477 件）・第220回（181 件）は母数が小さい。**
第217回の率 0.97% を当てると 218 は 4.6 件・220 は 1.8 件の期待値になるので、
**0 件であることはこの率と矛盾しない**（第216回の 4,258 件だと期待値 41 件なので、こちらは率だけでは説明できない）。

**第216回に 0 件である理由は、この測定では確かめられなかった。**
**その会期に参院の会議で発言した衆院議員が実際に何人いたかは、手元の `data/` からは分からない**
（突合できなかった発言のうち `position` を持つものは `unmatched.json` にも公開済み発言にも残らないため）。
**一次資料を取り直せば分かるが、本 PBI では取っていない。**

公開済み発言の日付から出した各会期の範囲（`data/` の実測。会期の正式な召集日・閉会日ではなく、
**発言が実際にあった日の最初と最後**である）:

```
第216回  2024-11-28 .. 2025-01-23  (4,258 件)
第217回  2025-01-24 .. 2025-06-21  (25,533 件)   ← unmatched 251
第218回  2025-08-01 .. 2025-09-12  (477 件)
第219回  2025-10-21 .. 2026-01-22  (5,684 件)    ← unmatched 50
第220回  2026-01-23 .. 2026-01-23  (181 件)
第221回  2026-02-18 .. 2026-08-26  (58,288 件)
```

**衆院名簿の `asOf`（2026-02-18）は第221回の最初の発言日と同じ日である。**
**名簿は第221回の入り口の 1 時点しか写しておらず、それ以前の 5 会期には何も言っていない。**

### **数えられない落ち**（母数の但し書き。#757）

`matchSpeeches`（`match-speeches.ts`）は、名簿に突合できなかった発言のうち
**`position`（`speakerPosition`）を持つものを `unmatched` に載せない**:

```ts
if (!s.position) unmatched.push({ nameText: s.speakerText, group: s.group ?? "", speechId: s.id, session: s.session });
```

これは設計どおりである（政府参考人・局長・参考人・公述人は議員でないので名簿に無いのが正常。`DATA_CONTRACT.md:172`）。
**だが副作用として、大臣・副大臣として答弁した衆院議員の発言も、同じ理由で `unmatched.json` に載らない。**
**その件数は `data/` からは数えられない**——公開済み発言にも `unmatched.json` にも残っていないからである。

**したがって「第216〜220回に落ちた衆院議員の発言は 301 件である」とは言えない。**
**言えるのは「301 件は `position` を持たない発言者のぶんであり、`position` を持つぶんは手元では数えられない」である。**
**数えるには会議録 API を取り直す必要がある**（本 PBI では取っていない）。

### **字形の罠ではない**（`WORKING_AGREEMENT.md` の 4 機序すべてを当てた）

**14 人 72 件について、氏名が壊れている形跡は 1 件も無い。**

**確かめられなかったこと**: **この 14 人が「2025 年の発言時点で衆院議員だったが 2026-02-18 現在では議員でない」のか、
そもそも別の立場（参考人など）で発言したのかは、手元の `data/` では区別できない。**

**引退・落選・改選・辞職のどれなのかは一次資料を見ないと分からず、本 PBI では取っていない。**
**「たぶん落選した元議員」とは書かない**（推測で議員を紐づけないのと同じ理由で、推測で経歴を書かない）。

- **採決側**: **参院名簿が第215回以前は公開されていない**（404。`sangiin-members.ts:14`、
  `DATA_CONTRACT.md:266`）ので、**第200〜214回のすべての票**が落ちる。
  その回次を名簿が直接覆う議員数を数えると **200〜215 は全回次 0 人**、216 以降は 240〜712 人である。

**この 22,818 件は既知で、文書化されている**（`DATA_CONTRACT.md:266` が
「これらの回次の票はほとんどが未突合として載る（上限を設けない。古い回次ほど多い）」と書いている）。
**`unmatched/{回次}.json` にも全 22,818 行が残っており、黙って捨てられてはいない**
（#219 の置き場所の規約どおり。`data/unmatched/` の 8 ファイル + 221.json の 1 行 = 22,819 行）。

### **発言側の B1 が採決側に波及することはない**

**採決に紐づいた 69,966 票は、すべて参院議員のものである**（衆院議員は 0 件）。
`cli.ts` は `matchVotes(rc, members)` を呼んでおり、`members` は `mergeRosters(rosters)`＝**参院名簿だけ**である。
衆院の個人別投票は公開されていないので、**衆院名簿の回次の狭さは採決側には届かない。**

### **`group-mismatch.json` の 211 件は別の機序で、この件とは無関係**

**211 行すべてが第217回の採決で、異なり議員は 2 人だけである。**

| 件数 | memberId | nameText | 採決ページの会派 | 名簿の会派 |
|---:|---|---|---|---|
| 136 | `m_021001` | 宮口 治子 | 各派に属しない議員 | 立憲民主・無所属 |
| 75 | `m_019007` | 梅村 みずほ | 各派に属しない議員 | 参政党 |

**これは「氏名で 1 人に絞れて在職も確認できたが、採決時点の会派表記が名簿と食い違った」ものである**
（`matchVotes` → `inAnyTerm`）。**票は正しく `memberId` が付いており、記録は落ちていない。**
`m_019007` の名簿は `[{sessionFrom:217, sessionTo:221, group:"参政党"}, {sessionFrom:216, sessionTo:216, group:"日本維新の会"}]` で、
**どちらの会派も「各派に属しない議員」ではない**——会期の途中で会派を離れたことが名簿に現れていないだけと読める
（`DATA_CONTRACT.md:157` の想定どおりの現れ方）。

**`group-mismatch.json` に「名簿にいない旧議員が同名の現職に紐づいた」形は見当たらない。**
**211 行の異なり氏名が 2 人しかなく、どちらも `sessionFrom`/`sessionTo` がその回次を覆っているため**、
**別人に紐づいた可能性を示す行は無かった。**
